# Meta Ads V319 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add full, human-approved Facebook/Instagram Ads read/write management to Mio without interfering with the Google Keyword Lab V318 work.

**Architecture:** Preserve the existing Meta reporting endpoint, add focused Meta workspace/service modules, persist audited mutation history in Supabase, and mount a dedicated Meta workspace in the Marketing area. All live writes are server-built from constrained action types, require explicit `APPLY` authorization, use idempotency/stale-resource checks, and are verified by re-reading Meta after mutation.

**Tech Stack:** React 19, Vite 8, Node/Vercel serverless, Meta Marketing Graph API, Supabase/Postgres/RLS, Node test runner, Playwright-core.

**Spec:** `docs/superpowers/specs/2026-09-13-meta-ads-workspace-v319.md`

## Global Constraints

- V318 belongs to `feat/keyword-lab-v318`; V319 belongs to `feat/meta-ads-workspace-v319`.
- Never commit V319 work onto the Keyword Lab branch or its local checkout.
- Do not merge or deploy either branch from this plan.
- AI is advisory only; no Meta write occurs without exact user authorization.
- Browser code may not submit arbitrary Graph paths/payloads.
- First live mutation must be low risk and must not be a budget increase or launch of a new active ad.
- If V318 merges first, update V319 from current `main`, resolve the Marketing/App seam, and rerun Meta plus relevant Google regression tests before merge.
