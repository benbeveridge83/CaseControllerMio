# Keyword Lab V318 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build one unified Keyword Lab for current keyword performance, keyword↔search-term mapping, keyword discovery, experiments, match-type controls, and review-before-write Google Ads changes.

**Architecture:** Extend the existing V317 Ads workspace and `/api/ads-workspace` action pattern. Keep Google Ads reads/writes in `lib/ads/*`, persist user classifications/experiments/planner cache in Supabase, and render a native React Keyword Lab under `src/ads` with four sub-tabs and a shared review basket. No core state goes to localStorage.

**Tech Stack:** React, Vite transform integration, Node/Vercel API routes, Google Ads API v25, Supabase/Postgres/RLS, Node test runner, Chromium browser tests.

**Spec:** `docs/superpowers/specs/2026-09-13-keyword-lab-v318.md`

## Global Constraints

- No automated test may mutate the live Google Ads account.
- Every live keyword/negative write requires explicit user approval.
- Uncertain write outcomes are never auto-retried.
- Unsupported Google metrics display `—`, not zero.
- Keyword/search-term attribution must use Google-reported triggering-keyword fields; never infer a criterion ID Google did not return.
- Match-type replacement creates/verifies the new criterion before pausing the old criterion.
- No localStorage for Keyword Lab core state.
