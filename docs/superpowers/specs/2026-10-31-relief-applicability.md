# Requested relief applicability

Approved direction: retain Settings > Requested Relief > Issue / option tree. Add configurable groups (Proceeding: Original, Modification; Order type: Final orders, Temporary orders, TRO). Rows/options receive applicability checkboxes during creation/edit. Children inherit, with optional narrower rules. Add a Filter groups settings subtab for adding/renaming groups and options. Archive rather than destructively delete referenced definitions.

Settings supports unrestricted/all, subsets, and explicit none per group. OR within groups, AND across groups. No selected context means unfiltered; explicit None matches nothing. Missing row restrictions inherit; existing top-level rows are unrestricted. The UI distinguishes inheritance from None. Filters do not mutate the tree or delete selections.

Matter issue and relief builders choose and persist context per saved set. Apply filtering to simple, split, multiple choice, template tree, and hidden-issue picker. Preserve snapshots, text, and selected IDs on context change, with explicit review/removal for selected choices excluded by context. Custom groups use stable IDs. No legal content classification is seeded. No authority/outlining feature is included.
