# Keyword Lab V318 — Design

## Goal
Replace the separate, limited Google Ads keyword/search-term controls with one unified **Keyword Lab** that lets the user (1) understand how current keywords are performing, (2) see exactly which search terms Google paired with which triggering keywords, (3) discover and test new keywords, and (4) safely change match strategy, add keywords, or add negatives through a review-before-write workflow.

The first optimization objective is **relevant clicks**. Conversion data remains visible but does not control the traffic-stage analysis while conversion tracking is sparse or unreliable.

## Existing foundation
Mio already retrieves Google Ads keyword metrics including impressions, clicks, CTR, average CPC, cost, conversions, campaign, ad group, status, and match type. The V317 Ads workspace already retrieves search-term rows including `segments.keyword.info.text` and `segments.keyword.info.match_type`, so Google-reported triggering-keyword ↔ search-term relationships are available in that workspace. V317 also provides review-before-write protections and Supabase-backed change history.

V318 extends those existing services rather than creating a second Google Ads subsystem.

## Navigation and page structure
The current top-level **Keywords** and **Search Terms** areas are consolidated into one top-level tab named **Keyword Lab**. The existing Negative Keywords area may remain available separately, but keyword/search-term actions can also queue negatives from inside Keyword Lab.

Keyword Lab has four sub-tabs that share the same global campaign, ad-group, and date controls:

1. **Current Keywords** — how existing keywords are doing and what searches they trigger.
2. **Search Terms** — what users actually typed and which keyword triggered each search.
3. **Find Keywords** — new candidates from manual seeds, existing terms, landing pages, and Google Keyword Planner.
4. **Experiments** — experimental keywords, start dates, hypotheses, and performance since each experiment began.

A persistent **Review Basket** button shows the count of queued live changes. Nothing changes in Google Ads until the user explicitly reviews and authorizes the basket.

## Shared date behavior
Keyword Lab supports:

- Last 7 days
- Last 14 days
- Last 30 days
- Last 90 days
- Custom start/end dates

Custom dates must be validated ISO dates and capped to a one-year reporting window. Per-day metrics use the number of calendar days in the effective range. For experiments, the effective start is the later of the selected start date and the experiment start date.

## Column-header controls
Column headers are controls, not static labels.

Clicking a header sorts ascending/descending. A filter control in the same header opens type-appropriate filtering:

### Numeric columns
Examples: impressions, impressions/day, clicks, clicks/day, CTR, CPC, cost, cost/day, conversions, conversion rate, cost/conversion, impression-share metrics.

Supported operators:

- greater than (`>`)
- greater than or equal (`>=`)
- less than (`<`)
- less than or equal (`<=`)
- equal (`=`)
- between
- nonzero
- blank / unavailable where a Google metric can be omitted

The filter chip must show the active rule, e.g. `CTR > 3%` or `Imp/day between 10 and 50`. Multiple column filters combine with AND. A clear-all control removes them.

### Text columns
Examples: keyword, search term, campaign, ad group.

Supported filters: contains, equals, does not contain.

### Categorical columns
Examples: status, match type, experiment state, recommendation.

Supported filters: one or more selected values.

### Date columns
Examples: experiment start date.

Supported filters: before, after, between.

Sorting and filtering operate on the currently selected date/campaign/ad-group scope and never alter Google Ads state.

### Expand a keyword to see its search terms
Clicking a keyword row expands it inline and shows **Search terms triggered by this keyword** for the selected date range.

Each child row shows:

- Search term
- Search-term match type
- Device when available
- Impressions
- Clicks
- CTR
- CPC
- Cost
- Conversions
- Classification
- Negative coverage
- Actions

The relationship shown is Google-reported triggering-keyword attribution from the search-term view, not an inference.

From the expanded list the user can:

- open the corresponding Search Terms sub-tab already filtered to that keyword
- classify the term relevant / irrelevant / observe
- queue the term as an exact or phrase keyword
- queue an exact or phrase negative

### Match-type controls
The Match column uses a dropdown/control for Exact, Phrase, and Broad.

Two distinct actions are supported:

- **Change match type** — replace the current strategy. The review basket shows old and new match types. Implementation creates the replacement criterion, verifies it, then pauses the old criterion rather than destroying historical visibility. If the second step is uncertain, Mio shows both current states and requires verification rather than retrying automatically.
- **Add another match type** — create an additional copy while leaving the current keyword untouched.

Changing the dropdown itself does not publish anything; it queues a reviewed change.

Bulk selection can queue a match-type change for multiple keywords at once. The review basket lists each exact destination ad group and old/new match type.

Pause/enable controls also go through the review basket. Remove is de-emphasized; routine experimentation should use pause so performance history remains understandable.

The Triggering Keyword value is clickable. Clicking it opens Current Keywords and expands that keyword.

- mark relevant

- mark observe

Bulk selection supports promotion/negative workflows through the review basket.

Search terms Google withholds for privacy are not fabricated; the page explains that the report is not a complete visitor log.

## Search-term quality and waste
Mio stores explicit user classifications instead of guessing relevance.

Metrics calculated over classified terms:

- Relevant-click rate = clicks from terms marked relevant or promoted / clicks from all classified terms.
- Relevant-spend rate = spend on terms marked relevant or promoted / spend on all classified terms.
- Waste rate = spend on terms marked irrelevant or later blocked as negatives / spend on all classified terms.
- Classified-spend coverage = classified spend / total search-term spend.

Unclassified terms are excluded from relevant/waste denominators. Coverage is always shown so a small classified sample cannot masquerade as a complete quality score.

## 3. Find Keywords tab
New candidate terms come from:

- manual entry
- selected search terms
- selected current keywords
- landing-page URL
- phrase + landing-page URL
- Google Keyword Planner / KeywordPlanIdeaService suggestions

Each candidate shows, when Google returns the data:

- Candidate phrase
- Source
- Estimated average monthly searches
- Monthly search history/trend
- Competition level
- Competition index
- Low top-of-page bid estimate
- High top-of-page bid estimate
- Whether an existing keyword already covers it
- Existing match types
- Whether an existing negative conflicts with it
- Related actual search terms already seen in the account
- Proposed campaign
- Proposed ad group
- Proposed match type
- Experimental toggle
- Optional hypothesis/note

Planner data is clearly labeled **estimated market demand** and never confused with actual account impressions.

Planner data is cached in Supabase with geo/language/network context and retrieval timestamp.

Competitor names can be entered as normal planner seeds to estimate search demand for those phrases.

## 4. Experiments tab
Experimental keywords are deliberately tracked instead of blending silently into the core set.

Stored fields:

- Google criterion/resource identifier after verified creation
- Keyword
- Match type
- Campaign/ad group
- Source: manual, planner, or search-term discovery
- Hypothesis/note
- Experiment start time
- Approver
- State: proposed, approved, active, paused, promoted-to-core, ended

Performance is measured from the experiment start date, not from earlier account history.

The table shows raw totals plus per-day metrics and sample size. A keyword with 2 impressions and 50% CTR must never look more trustworthy than a keyword with 1,000 impressions and 8% CTR without clearly showing the volume difference.

Actions:

- promote to core
- continue test
- pause experiment
- change/add match type
- inspect triggered search terms

## Recommendation badges
Recommendations are transparent rule-based labels, for example:

- Keep / scale
- Keep but tighten
- Test longer
- Add negative protection
- Pause candidate
- Insufficient data

A badge exposes its reasons, e.g. `High impressions/day + low CTR + many irrelevant terms -> tighten / add negatives`.

Thresholds live in one centralized configuration module and are unit-tested.

## Review Basket and authorization
All live keyword and negative-keyword actions use the existing V317 review-before-write model.

Queueable actions:

- add keyword
- add experimental keyword
- add another match type
- replace/change match type
- pause keyword
- enable keyword
- add campaign negative
- add ad-group negative

Before authorization the basket shows:

- action type
- campaign
- ad group
- keyword/negative text
- old match type/status
- proposed match type/status
- experimental flag
- source/hypothesis when applicable

Editing any queued item resets authorization. Explicit approval is required before any live call. Every mutation is validated first and then verified with a fresh Google Ads read. Uncertain results are never auto-retried.

Actions:

### Keyword/search-term mapping
The search-term query must include Google-reported triggering keyword text, triggering keyword match type, and enough criterion identity to reliably link the row back to the current keyword where the API supplies it. If Google omits identity on a row, Mio may display the text/match type but must not invent a criterion ID.

The keyword snapshot includes performance metrics over the selected date range rather than returning only static inventory.

### Match-type replacement safety
For `change_match_type`, Mio validates the intended replacement, creates the new criterion, reads it back, and only then pauses the old criterion. If create verification fails, the old keyword remains unchanged. If pausing the old criterion is uncertain, the result is marked unverified and no automatic retry occurs.

## Supabase persistence
Create focused cloud tables; do not use localStorage for core state.

### `mio_ads_keyword_experiments`
Experiment metadata/lifecycle.

### `mio_ads_keyword_market_cache`
Keyword Planner cache keyed by normalized seed/context and retrieval time.

### `mio_ads_search_term_classifications`
User classifications and notes for account/campaign/ad-group/search-term identity.

Existing V317 mutation-history tables remain the source of truth for approvals/results.

RLS restricts all tables to authenticated Beveridge Law Firm users consistent with the current Ads workspace policies.

## Competitor / Auction Insights
V318 may attempt aggregate Auction Insights read-only reporting when Google exposes it through the connected API account. If unavailable, show `Auction Insights unavailable from API` without breaking Keyword Lab.

If available, only aggregate metrics are shown: participant domain, impression share, overlap rate, position-above rate, top-of-page rate, absolute-top rate, and outranking share. Mio never claims a competitor received a particular user's search.

## Error handling
- Unsupported/omitted metrics display `—`, not zero.
- If Keyword Planner is unavailable, Current Keywords and Search Terms still work.
- If a planner keyword has low/omitted volume, absence is not described as proof of zero searches.
- If Auction Insights is unavailable, only that panel shows unavailable.
- If inventory needed for safe mutation is incomplete, live action controls are disabled.
- Failed writes preserve the review basket and show Google's returned error/request ID when available.
- Uncertain writes require read-only reconciliation or a fresh approval.

## Testing
1. Unit tests for date normalization, per-day rates, numeric/text/date/categorical column filters, stable sorting, experiment-day normalization, keyword/search-term grouping, recommendation rules, quality/waste metrics, and match-replacement planning.
2. Service/API tests for keyword performance queries, triggering-keyword attribution, planner normalization/cache behavior, custom date validation, review validation, change-match create/verify/pause ordering, stale criterion protection, partial/uncertain results, and optional Auction Insights failure.
3. Browser tests for all four sub-tabs, header operator filters, sort toggles, inline keyword expansion, click-through keyword ↔ search-term navigation, match dropdowns, bulk match changes, candidate selection, classification, review-basket authorization reset, and error states.
4. Regression tests for existing V317 ad editor, audience, search-term negative workflows, Google Ads auth/write gates, and Formspree/billing unaffected areas.
5. Production build validation.
6. No automated test may mutate the live Google Ads account.

## Success criteria
V318 is successful when the user can:

1. Open one Keyword Lab instead of bouncing between separate Keywords and Search Terms pages.
2. Sort and filter every important metric directly from the column header, including rules such as `Impressions/day > 10` or `CTR < 2%`.
3. See actual keyword performance with impressions and per-day rates.
4. Change or add Exact/Phrase/Broad match strategy from Mio through a review basket.
5. Expand any keyword to see Google-reported search terms it triggered.
6. See the triggering keyword on each search-term row and jump back to that keyword.
7. Promote good search terms to keywords and bad terms to negatives.
8. Discover experimental candidates using actual search terms and Keyword Planner market-demand data.
9. Track experiments from their own start dates.
10. Explicitly approve every live Google Ads mutation and retain Supabase-backed history.

## Explicit non-goals
- No autonomous keyword creation, pausing, or match-type changes.
- No AI system publishes Google Ads changes without explicit user approval.
- No opaque magic effectiveness score replaces raw metrics.
- No claim that Auction Insights ties a competitor to a particular search.
- No dependency on Auction Insights or perfect conversion tracking.
