# Keyword Lab V318 — Design

## Goal
Turn Mio's existing Google Ads Keywords area into a practical keyword-selection and audit system that helps answer three questions:

1. Which current keywords are actually creating useful opportunity and traffic?
2. Which real search terms should become keywords or negatives?
3. Which new experimental keywords are worth testing based on market demand, competition, and expected cost?

The first optimization objective is relevant clicks. Conversion metrics remain visible, but the interface must not suppress promising keywords merely because conversion tracking is sparse or unreliable.

## Existing foundation
Mio already retrieves Google Ads keyword metrics including impressions, clicks, CTR, average CPC, cost, conversions, match type, campaign, and ad group. It also retrieves search-term data and negative keywords. The V317 Ads workspace already provides a review-before-write pattern for Google Ads mutations and stores approval/history data in Supabase.

V318 extends that existing architecture rather than creating a separate marketing subsystem.

## Primary UI: Keyword Lab
The current Keywords tab becomes the Keyword Lab. It contains three working views that share the same campaign/ad-group/date filters.

### 1. Current Keywords
Displays every current keyword with sortable columns:

- Keyword
- Status
- Match type
- Campaign
- Ad group
- Impressions
- Impressions/day
- Clicks
- Clicks/day
- CTR
- Average CPC
- Cost
- Cost/day
- Conversions
- Conversion rate
- Cost per conversion
- Search impression share when Google reports it
- Search lost impression share (rank) when Google reports it
- Search lost impression share (budget) when Google reports it
- Top impression rate when supported
- Absolute top impression rate when supported
- Experiment status
- Experiment start date
- Data-age / sample-size indicator

The table supports one-click sort presets:

- Most opportunity — impressions/day
- Most traffic — clicks/day
- Best CTR
- Lowest CPC
- Best conversion efficiency
- Most wasted spend
- Needs more data
- Experimental only

No opaque composite score is required for V318. Mio may show a transparent recommendation badge based on the underlying metrics, but the raw measures remain primary.

### 2. Search-Term Discoveries
Search terms are treated as evidence about how Google's matching actually behaves.

For each term, Mio shows:

- Search term
- Triggering keyword where Google exposes it
- Campaign / ad group
- Search-term match type
- Impressions
- Clicks
- CTR
- CPC
- Cost
- Conversions
- Whether already targeted as a keyword
- Whether already blocked by a negative
- Suggested action

Suggested actions are advisory only:

- Promote to keyword
- Add as exact keyword
- Add as phrase keyword
- Add as negative exact
- Add as negative phrase
- Leave alone / observe

A user can select one or more terms and place them into the review basket. No live mutation occurs from the row itself.

### 3. Experimental Candidates
Candidate terms come from three sources:

- Manual entry
- Search-term discoveries
- Google Keyword Planner / KeywordPlanIdeaService suggestions and historical metrics

For each candidate Mio displays, when available:

- Candidate phrase
- Source
- Estimated average monthly searches
- Monthly search history / trend
- Competition level
- Competition index when available
- Low top-of-page bid estimate
- High top-of-page bid estimate
- Whether a current keyword already covers it
- Whether it conflicts with an existing negative
- Related search-term evidence from this account
- Proposed campaign / ad group
- Proposed match type
- Experimental label

Keyword Planner data is cached in Supabase with the retrieval timestamp because market-volume data does not need to be refreshed on every page load.

## Experiment model
A keyword added through the Keyword Lab can be marked Experimental at creation.

For an experimental keyword Mio stores:

- Google Ads criterion/resource identifier after successful creation
- Keyword text
- Match type
- Campaign and ad group
- Experiment start time
- Who approved it
- Source: manual, planner, or search-term discovery
- Optional hypothesis/note
- Status: proposed, approved, active, paused, promoted-to-core, ended

Performance for experiments is measured from the experiment start date when possible, not from a longer account-wide date range that predates the experiment.

Mio must make sample size visible. A keyword with 2 impressions and 50% CTR must not be visually ranked as more trustworthy than one with 1,000 impressions and 8% CTR without clearly showing the data volume.

## Keyword recommendation logic
Recommendations are rule-based and transparent in V318. The interface can label a keyword as:

- Keep / scale
- Keep but tighten
- Test longer
- Add negative protection
- Pause candidate
- Insufficient data

The badge must expose its reasons, for example:

`High impressions/day + low CTR + no conversions + broad matching -> inspect search terms / tighten`

or:

`Low volume + strong CTR + high-intent search terms -> keep; insufficient volume to scale`

Thresholds belong in one centralized configuration module so they can be adjusted without rewriting components.

## Search-term quality and waste
V318 adds account-level evidence rather than pretending Google can directly label a search as good or bad.

Mio calculates:

- Search-term quality rate = clicks/cost from user-approved relevant terms compared with all classified terms
- Waste rate = spend from terms the user marks irrelevant or terms later blocked as negatives divided by classified spend

Unclassified search terms remain unclassified and are not silently counted as bad.

This gives the keyword audit an evidence loop:

keyword -> actual search terms -> user classification -> negatives/promotions -> later performance

## Market-demand data
Mio should use Google's keyword-planning APIs for new ideas and historical keyword metrics where available.

The system should support seed input from:

- Existing keyword text
- Selected search terms
- A manually entered phrase
- A landing-page URL only if the API permits the requested idea-generation mode

Market data is advisory. It must be labeled as estimated/historical demand rather than actual impressions Mio received.

Mio should distinguish clearly between:

- Estimated monthly searches from Keyword Planner
- Actual impressions from the user's account
- Impression share, which estimates the percentage of eligible impressions captured

These are different measurements and must never be merged into one number.

## Competitor evidence
V318 may surface competitor evidence when Google reports Auction Insights-compatible metrics at supported scopes. This is not individual search-term attribution.

Mio may show, separately from the keyword table:

- Competitor/domain
- Impression share
- Overlap rate
- Position-above rate
- Top-of-page rate
- Absolute-top rate
- Outranking share

The UI must not claim that a specific competitor received a specific user's search unless Google explicitly supplies that relationship.

## Review basket and authorization
All live keyword and negative-keyword writes use a review basket consistent with V317.

The user may queue actions such as:

- Add keyword
- Add experimental keyword
- Change keyword match type by replacing the criterion safely
- Pause keyword
- Enable keyword
- Add campaign negative
- Add ad-group negative

Before authorization, the review screen shows the exact intended mutation, including:

- Campaign
- Ad group
- Keyword or negative text
- Match type
- Current state
- Proposed state
- Experimental flag

Only explicit user approval starts the Google Ads mutation. The service verifies the resulting state with a fresh read-back before marking the item successful. Uncertain writes are not auto-retried.

## Backend/API changes
Extend the existing ads workspace service rather than creating an unrelated API stack.

Likely service capabilities:

- `keyword_lab_snapshot` — current keyword metrics plus available impression-share/rank metrics
- `keyword_candidates` — cached and/or live Keyword Planner ideas
- `keyword_history` — historical planner metrics for supplied terms
- `keyword_experiments` — experiment metadata/history from Supabase
- `keyword_review` — validate a proposed basket without writing
- `keyword_apply` — authorized mutation batch using the same approval/write-mode protections as V317
- `keyword_verify` — fresh read-back of the requested mutation results

The exact route names may be folded into the existing `/api/ads-workspace` action pattern if that produces less duplication.

## Supabase persistence
Add focused tables rather than browser local storage.

### `mio_ads_keyword_experiments`
Stores experiment metadata and lifecycle state.

### `mio_ads_keyword_market_cache`
Stores planner metrics/ideas with account, phrase, geo/language context, retrieval time, and normalized metrics.

### `mio_ads_search_term_classifications`
Stores user classification of real search terms such as relevant, irrelevant, observe, or promoted, plus notes and timestamps.

Existing V317 change-history tables remain the source of truth for mutation approvals/results.

RLS should restrict these tables to authenticated Beveridge Law Firm users, with mutation-history controls consistent with the existing Ads workspace.

## Date behavior
The Keyword Lab has a shared date selector:

- Last 7 days
- Last 14 days
- Last 30 days
- Last 90 days
- Custom date range if supported by the existing reporting layer

Per-day metrics divide by the actual number of calendar days in the selected range unless experiment mode uses the later experiment-start date.

The UI should show both the raw total and normalized per-day value so users can distinguish volume from rate.

## Error handling
- If Keyword Planner is unavailable, Current Keywords and Search-Term Discoveries still work.
- If a metric is unsupported at a selected scope, display `—`, not zero.
- If Google omits low-volume data, explain that the absence is not proof of zero searches.
- If a write fails, preserve the basket and show Google's returned error and request id when available.
- If mutation outcome is uncertain, do not auto-retry; require verification or a fresh user-approved attempt.
- No marketing page should depend on localStorage for core state.

## Testing
Implementation should include:

1. Unit tests for impressions/day, clicks/day, cost/day, experiment-day normalization, recommendation rules, dedupe, and search-term classification math.
2. API/service tests for planner result normalization, cache behavior, unsupported metrics, review validation, stale-resource protection, and authorized writes.
3. Browser tests for sorting, preset filters, adding candidates to the basket, promoting search terms, adding negatives, experiment labeling, and approval reset after edits.
4. Regression tests for existing V317 Ads editor/search-term workflows.
5. Production build validation.
6. No automated test may mutate the live Google Ads account.

## Success criteria
V318 is successful when the user can:

1. Sort existing keywords by opportunity, traffic, CTR, CPC, cost, and conversion efficiency.
2. See impressions/day and other normalized rates next to raw totals.
3. Inspect the actual search terms produced by a keyword/ad group and classify them.
4. Turn good search terms into proposed keywords and bad terms into proposed negatives.
5. Generate or enter experimental candidate keywords and compare estimated search demand, competition, and bid ranges.
6. Label newly approved keywords as experiments and evaluate them from their own start date.
7. Review all proposed Google Ads writes in one basket and explicitly approve them before anything changes live.
8. Preserve a complete Supabase-backed history of experiment state and approved mutations.

## Explicit non-goals for V318
- No autonomous keyword creation or pausing.
- No AI system is allowed to publish changes without the user's explicit approval.
- No single opaque 'magic effectiveness score' replaces the underlying metrics.
- No claim that Auction Insights identifies which competitor received a particular search.
- No dependence on conversion tracking being perfect before keyword traffic can be analyzed.
